# AI-Use Plan (Draft)

**Status:** draft for the group to review. The group writes the final wording. The instructor's rules for AI use are not known yet, so this must be checked against them (see `PLAN.md`, open questions).

## Purpose

This plan says which AI tool may help with which tasks, how the group checks the output, and how the group records what it changed. It becomes the AI-use declaration in the final documentation.

## Tool

| Tool | Allowed help |
| --- | --- |
| Claude | Help with documentation drafts and with code review: finding mistakes, suggesting simpler code, checking edge cases. |

The group may add or remove tools in the final version.

## Tasks and Checks

| Task | AI may help | How the group checks it |
| --- | --- | --- |
| Documentation drafts (design, test plan, user guide outline) | Yes, as a first draft | Members read every line, correct it against the real app, and rewrite it in their own words. |
| Code review | Yes, as a second pair of eyes | Members decide what to change. Every change is built and tested before it is kept. |
| Test case ideas | Yes | Members run each case themselves. Results are never copied from AI. |
| Defects and improvements log | No | Members write only what they really saw. |
| Final app code | Group decision (to fill in) | If AI helped, members must be able to explain every line. |

## Rules for the Group

- First, a member reviews every AI output before it is used.
- Then the member tests it, or checks it against the code or the assignment sheet.
- Finally, the member records what was used and what was changed.
- AI output is never trusted for facts about Android versions, permissions or APIs without checking the official Android documentation.
- No personal data, real health data or secrets are given to an AI tool.
